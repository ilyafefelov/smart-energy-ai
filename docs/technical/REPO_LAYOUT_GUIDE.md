# Repo Layout Guide

This guide explains how to read the repository without treating every top-level
folder as equally active.

## Root Categories

### Active Runtime Code

- `src/` - primary backend runtime and Dagster assets
- `scripts/` - operational entrypoints and local tooling wrappers
- `energy_ml/` - reusable domain/runtime logic and compatibility surfaces
- `dashboard/` - active Nuxt frontend application
- `tests/` - validation suites aligned to active runtime surfaces

### Documentation And Deployment

- `docs/` - active technical and deployment reference material
- `docker/` - container and workspace configuration
- `deploy/` - service and host deployment assets

### Runtime Output And Working State

- `data/` - local Dagster home plus working raw/processed/result data
- `artifacts/` - exported local artifacts and ad hoc run outputs
- `logs/` - execution logs
- `models/` - model binaries and tenant-scoped artifacts
- `plots/` - generated chart output

These folders are useful operationally, but they should not grow into new
source-of-truth code locations.

### Legacy And Reference

- `archive/` - archived applications, reports, and historical snapshots
- `projects/` - nested or external project references retained in the workspace

Keep legacy material out of active runtime flows unless a migration task
explicitly promotes something back into the main surface.

### Tooling And Local Agent State

- `.github/` - repository automation and instruction overlays
- `.beads/`, `.desloppify/` - tracking and code-health tooling state
- `.claude/`, `.kilocode/`, `.playwright-mcp/` - local AI/tool integration state
- `.venv/`, `.pytest_cache/`, `__pycache__/` - environment and cache directories

These folders are intentionally excluded from broad folder-README generation.

## Folder README Policy

- Active tracked folders should have `README.md` coverage.
- Existing curated `README.md` files should be preserved rather than replaced.
- The autogenerated index section inside a folder README is refreshed with
  `scripts/generate_folder_readmes.py`.
- Generated, vendor, cache, and archive-heavy subtrees are excluded on purpose
  to avoid noisy, low-value documentation churn.

## Root Flattening Direction

The repository is still flatter than ideal. The current safe direction is:

1. Keep `src/` as the main backend runtime surface.
2. Keep `scripts/` thin and move reusable logic out of script entrypoints.
3. Keep `energy_ml/` focused on domain/runtime helpers and compatibility paths.
4. Keep runtime-output folders clearly documented as outputs, not code owners.
5. Move only with validation; do not reorganize paths speculatively.

This means documentation and folder ownership should improve first, while actual
directory moves happen only when a validated migration path is clear.
