# S3 Pickle IO Manager

## Purpose

This runbook defines the S3 artifact persistence setup used by Dagster asset materialization.

## Configuration

Set these environment variables for S3-backed persistence:

- `S3_IO_MANAGER_BUCKET`: target S3 bucket name (required to enable S3 mode)
- `S3_IO_MANAGER_PREFIX`: key prefix root (default: `smart-energy-ai/assets`)
- `S3_IO_MANAGER_MAX_RETRIES`: retry attempts for transient S3 errors (default: `3`)
- `AWS_REGION` or `AWS_DEFAULT_REGION`: AWS region for S3 client

If `S3_IO_MANAGER_BUCKET` is not set, Dagster automatically falls back to filesystem IO manager.

## Key Naming Convention

The IO manager writes pickled payloads with deterministic keys:

```text
{S3_IO_MANAGER_PREFIX}/{identifier-segments}/partition={partition_key}.pickle
```

Examples:

```text
smart-energy-ai/assets/tenant/client_001_kyiv_mall/client_data_client_001_kyiv_mall/result.pickle
smart-energy-ai/assets/tenant/client_001_kyiv_mall/client_data_client_001_kyiv_mall/result/partition=2026-03-03.pickle
```

Notes:

- Asset-key segments are sanitized to alphanumeric + `._=-` with `_` replacement.
- Tenant asset paths generated by the asset factory include tenant namespace in the key path.
- Partitioned assets append `partition={partition_key}`.

## Bucket Layout

Recommended bucket layout:

```text
s3://<bucket>/smart-energy-ai/
  assets/               # Dagster IO manager payloads
  checkpoints/          # model checkpoints
  exports/              # analytics exports and reports
  logs/                 # optional structured logs
```

## Retention and Lifecycle Rules

Recommended lifecycle policy:

- `assets/`: transition to Standard-IA after 30 days, Glacier Instant Retrieval after 90 days, delete after 365 days.
- `checkpoints/`: keep latest model families, transition to IA after 30 days, delete non-pinned versions after 180 days.
- `exports/`: transition to IA after 14 days, delete after 180 days.
- `logs/`: delete after 30-90 days depending on compliance requirements.

## Failure Handling

- IO manager retries S3 `put_object` and `get_object` with exponential backoff.
- If S3 initialization fails at startup (for example, missing credentials or boto3), the system falls back to filesystem IO manager and logs a warning.

## Validation

1. Run a Dagster materialization with `S3_IO_MANAGER_BUCKET` set.
2. Verify outputs are written to expected S3 key paths.
3. Re-run dependent assets and verify successful object reload from S3.
