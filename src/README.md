# src

Primary backend runtime and Dagster asset code for the active system.

This is the main backend surface for current runtime work. Dagster loads from `src.definitions`, and reusable extraction targets should generally land under `src/data_pipeline/` rather than re-expanding large orchestration modules.

## Working Guidance

- Treat `src/definitions.py` as the active Dagster entrypoint.
- Keep shared data shaping, fallback generation, and validation helpers under `src/data_pipeline/`.
- Prefer keeping `src/assets/` focused on orchestration and asset-contract boundaries instead of embedding heavy helper logic directly in asset modules.
- For local-stack behavior and operations context, pair this folder with `docs/technical/` and `docs/deployment/` references.
